O problema, em uma frase

Entregável 1

Registro por id e lucro do período

  1. Ids chegam a 109 e há até 5000 vivos: vetor por id é inviável. Usamos um dict (tabela hash).
  2. Guardamos também total, a soma de todos os lucros.
  3. INSERIR soma o lucro; LUCRO soma só a diferença (novo − antigo).
  4. Fim do lote: Lk = total, sem percorrer depósitos.

Complexidade: INSERIR e LUCRO em O(1) esperado; obter Lk em O(1). Espaço O(n).

Entregável 1

Pilha de prosperidade

  1. Lk > 0: empilha (k, Lk).
  2. Lk = 0: nada muda.
  3. Lk < 0: o prejuízo consome o topo; se sobra, desempilha e continua no próximo.
  4. A soma dos resíduos fica num acumulador, então PROSPERIDADE só lê base, topo e soma.

Amortizado O(1): cada período empilha no máximo 1 elemento, e cada elemento sai uma única vez. Em P períodos são ≤ P desempilhamentos no total (pior período isolado: O(h)).

Entregável 1

MELHOR: Kadane online

  1. Recorrência: suf(k) = Lk + max(0, suf(k−1)): estende o intervalo corrente ou recomeça em k.
  2. Estende com soma anterior ≥ 0: no empate fica o menor i.
  3. O melhor global só troca com soma estritamente maior: no empate fica o menor j.
  4. O intervalo nunca é vazio, mesmo com todos os L negativos.

Complexidade: registrar um período e responder MELHOR em O(1), com 5 inteiros de estado (espaço O(1)); não guardamos o histórico.

Entregável 2

Heap indexado: alterar o lucro

  1. Heap de mínimo ordenado pelo lucro: o menor lucro fica sempre na raiz.
  2. Um dict pos (id → posição) acha qualquer depósito sem varrer o heap.
  3. LUCRO troca a chave: se diminuiu, sobe (_subir); se aumentou, desce.
  4. Cada elemento movido tem sua posição atualizada em pos.

Complexidade: achar o id O(1) esperado + reposicionar O(log n). Por isso não usamos heapq, que não altera a chave de um elemento qualquer.

Entregável 2

REMOVER sem varrer todos

  1. A raiz do heap é o menor lucro.
  2. Enquanto lucro < T (estrito), extrai a raiz, apaga o depósito e conta.
  3. Quando a raiz é ≥ T, ninguém mais está abaixo: para na hora.
  4. Imprime a quantidade removida.

Complexidade: O(k log n) para k removidos: só toca em quem será fechado, nunca nos n depósitos todos. Depósito abaixo de T continua vivo até o REMOVER.

Entregável 2

PAR: divisão e conquista (1/2)

  1. Ordena os pontos por x uma vez e divide ao meio.
  2. Resolve cada metade recursivamente (δE, δD) e fica com δ = o menor.
  3. Devolve também os pontos ordenados por y (como um merge sort) para o nível de cima.
  4. Tudo em inteiros: comparamos distâncias ao quadrado.

Por quê? Comparar todos os pares é O(n²). Dividindo, o trabalho de cada nível é linear e há log n níveis.

Entregável 2

PAR: a faixa central (2/2)

  1. Um par melhor que δ pode ter um ponto em cada metade; ambos estão a menos de δ da reta divisória: a faixa.
  2. Percorre a faixa ordenada por y e só compara com os próximos enquanto dy < δ.
  3. Cada ponto vê no máximo 7 vizinhos (casa dos pombos num retângulo 2δ×δ).
  4. Distância final = teto da raiz: isqrt(d²) (+1 se não for exata).

Complexidade: T(n) = 2T(n/2) + O(n) = O(n log n) por consulta. Sem matriz nem heap de distâncias; guardamos só o último resultado (cache).

Entregável 3

Grafo com listas de entrada e de saída

  1. saida[u] = {v: custo}: rotas que saem de u.
  2. entrada[v] = {u}: quem tem rota para v.
  3. INSERIR adiciona a rota nas duas listas.
  4. Remover u: percorre saida[u] e entrada[u], apagando u dos vizinhos, e depois apaga u.

Por que duas listas? Só com a de saída, achar quem chega em u custaria O(n + m). Com as duas, remover custa O(grau de u). Matriz de adjacência gastaria O(n²) de espaço; a lista usa O(n + m).

Entregável 3

DIST: Dijkstra com o heap do Entregável 2

  1. Começa com dist[s] = 0 e s no heap.
  2. Extrai o vértice de menor distância provisória: ela vira definitiva.
  3. Relaxa suas rotas: se dist[u] + c < dist[v], atualiza v (decrease-key; insere se for novo).
  4. Repete até o heap esvaziar; quem não foi alcançado vale −1.

Por que funciona: com custos ≥ 1, nenhum caminho por vértice ainda aberto pode ser mais barato que o menor provisório.
Complexidade: n extrações + até m decrease-keys, cada um O(log n): O((n + m) log n).

Entregável 3

Como o Entregável 3 gera a saída

  1. O Dijkstra devolve a distância dos alcançáveis.
  2. Os ids vivos são ordenados (não são contíguos, vão até 109).
  3. Para cada id ≠ s imprime a distância ou -1.
  4. Se s é o único vivo, a linha sai vazia.

Juntando tudo: REMOVER usa o heap de lucros (E2) e apaga o depósito do grafo; DIST usa outra instância da mesma classe de heap. INSERIR: O(log n + r); REMOVER: O(k log n + graus); DIST: O((n+m) log n + n log n).

Como testamos

  • Referência ingênua (força bruta) das 7 operações, conferida com o exemplo do enunciado.
  • 400 entradas aleatórias por entregável, comparando saída linha a linha: 0 falhas em 1200 execuções.
  • Valores pequenos de propósito, para forçar empates, prejuízo que zera a pilha, inalcançáveis e remoção com rotas.
